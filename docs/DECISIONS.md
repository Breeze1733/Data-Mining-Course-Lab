## D1 2026-10-30 P1 句子级叙述焦点的标注口径

**问题**：五类标签（黄山/九寨沟/颐和园/景区外/无法判断）的判定边界需要明确约定，
否则预标注不可复现、下游过滤行为无法解释。

**选项**：
- A. 按记录主景区标签派生（零成本但等于基线 A，无法度量改进）；
- B. 按句子叙述焦点人工判定（成本高但直接度量"约 1/3 句子在说景区外"的瓶颈）；

**选择**：B。口径细则：
1. **景区内（黄山/九寨沟/颐和园）**：句子叙述焦点是该景区范围内的游览要素——
   景点、园内交通（索道/观光车/园内步道/摆渡车）、园内设施（山上酒店/厕所/缆车站）、
   门票与开放规则、官方路线与时段建议。
2. **景区外**：焦点在景区范围之外——周边联游景区（黄龙/宏村/磁器口/乐山等）、
   山下/沟口/市区酒店餐饮购物、往返大交通（航班/高铁/自驾抵达）、平台广告与
   无关声明、纯城市游内容（多景点游记中的其他城市段落）。
3. **无法判断**：代词悬空且句内无景区线索（含上下文仍不足）、纯表情/语气碎片、
   真并列无主次的多景区句（如"九寨黄龙联票"并列讨论）。
4. 上下文使用：允许参考同记录的前一句辅助判定悬空指代；不使用记录级主景区标签
   作为判定依据（它正是基线 A，用了会让对比失效）。
5. 酒店归属：山上/园内住宿算景区内（游览连续性的一部分）；沟口/山下/市区算景区外。

**下游含义**：该标签用于过滤实体抽取、共指候选与条件建议——标为"景区外"的句子
不应向对应景区的图谱贡献 POI/条件/消解候选。

## D2 2026-10-30 P1 归属过滤接入实验4/5 的默认行为

**问题**：方案B句级归属（U5 冻结）是否作为实验4消解候选过滤与实验5条件对提取的默认行为？

**证据**：
- 实验4：过滤后 123/1940（6.3%）消解结果改变（景区外句候选被剔除、回退景区名），120 例黄金集
  准确率 0.425 持平、按类持平——零退化，候选池语义更干净。
- 实验5：条件对 1210→867（-28.3%）。49 例黄金复核中，景区外句含 3 wrong + 2"抽取正确但归属
  错误"（故宫/黄龙的贴士挂在颐和园/九寨沟名下）+ 1 纯外部边界；抽查被移除对全部为民宿好评、
  航班餐饮、联游城市餐馆等噪声。黄金样层面上 correct 率 40.8%→43.9%（18/41）。

**选择**：两处均默认开启，提供 `--no-attribution-filter` 逃生门；报告5/6 已重生成并通过一致性审计。

**已知代价（如实记录）**：
1. 抵达类贴士（如"普速到老火车站→建议换乘班车前往黄山景区"）按 D1 口径属大交通=景区外，
   会被过滤——"如何抵达"类知识从图谱条件集中消失是设计内取舍；若需保留可在此后单元引入
   "抵达类独立通道"。
2. 混合句（如"从新建宫门出去打车吃饭…体力好的还可以沿湖走"）可能被整体误滤（黄金集中约 1-2 例）。

## D3 2026-10-30 方案C（LLM 句级归属 0.887）是否接入生产管线

**问题**：方案C（LLM few-shot，495 句 0.887 vs 方案B 特征规则 0.796）显著优于方案B，
是否把实验4/5 的归属过滤换成 LLM 实现？

**选项**：
- A. 生产管线换 LLM：质量最高（归属过滤更准），但 271 记录≈1.4 万句需逐句调用——冒烟链
  从分钟级变成小时级、消耗 API 配额，且行为依赖外部服务稳定性；无 key 的克隆退回方案B
  （两套行为，复现口径分裂）。
- B. 生产保持方案B（无 key 可复现），方案C 作为度量上界与可选增强记录；
  未来如需质量可做"混合"（方案B 低置信句才调 LLM，约 15% 句量）。

**选择**：B。理由：课程实验的可复现性承诺（README 冒烟链无外部依赖）优先于最后 9 个点的
归属精度；方案C 结果已完整落盘（llm_attribution_eval.json 逐例），混合方案作为后续选项记录。

## D4 2026-10-31 消解黄金集扩容 120→180 与开发/留出双口径

**问题**：task4 的 120 例标注既承担规则迭代又承担报告口径，第2轮规则（0.583）是在同一批例句上
反复修复后的结果，对开发集的适应程度无法度量；继续在此集上迭代有过拟合风险。

**选择**：扩容 60 例（seed=43、每格 5 例、排除已标注 case，EXPAND_GOLD 由标注者按上下文独立判定，
不看规则输出定判），并入 annotation_gold.json（追加式，原 120 行不动，标记 round=2）。

**口径约定**：
1. 第 1 轮 120 例 = 开发集（允许规则迭代查看错误）；
2. 第 2 轮 60 例 = 留出集（holdout）——规则改动**不在其上逐例调试**，每个单元只做终评对照；
3. 报告与 METRICS 主口径改为 180 例总体准确率（当前 0.483 = 开发 0.583 / 留出 0.283），
   并同时报告分轮数字；evaluation.json 新增 accuracy_by_round / errors_by_round；
4. 打分器 canon 与判定逻辑不变（历史可比）；0.483 取代 0.583 成为守护指标 task4.coref_accuracy 的新基准，
   已 --update-state 留痕（本轮变更见 PROGRESS U21）。

**扩容的直接发现**：留出集 28.3% vs 开发集 58.3%——证实了此前 0.425→0.583 的提升中相当一部分
是对开发集的适应；四大错误机制占比：回退景区名 31%、判同行者 27%、集合类机制 23%、实体体系外先行词 19%。
